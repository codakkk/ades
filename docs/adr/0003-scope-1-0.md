# 1.0 scope boundary

Core 1.0 = **CAdES + PAdES**: create and validate, B-B through B-LTA, with trusted-list qualification. XAdES is **verify-only** in 1.0, limited to the enveloped profile trusted lists use. Legacy read: BES/EPES/T fully, XL validated as B-LT, CAdES-A ATSv3. ATSv2 is best-effort and yields INDETERMINATE with a reason, never a silent pass. `.tsd` (RFC 5544) is unwrapped.

This is a single-maintainer project, and the full DSS-scale matrix would keep 1.0 from ever shipping. CAdES (`.p7m`) and PAdES cover almost all of the Italian volume while keeping the hard engine work (EN 319 102-1, trusted lists, qualification) in 1.0.

Later: 1.1 adds XAdES creation and full verification. 1.2 adds ASiC-S/E. After that: JAdES, PAdES visible-signature appearance (1.0 creates an empty-widget field only), TS 119 102-2 XML report serialization (1.0 has an in-memory model that maps to it 1:1), `.m7m`, a DSS `constraint.xml` importer.

Never: creation of -C/-X forms, evidence records (RFC 4998), signature-policy enforcement (SigPolicyId is parsed, not enforced), PDF rendering or visual comparison.

DSS (LGPL-2.1) is a black-box validation oracle only and is never ported line by line. All packages are Apache-2.0. `ades-rs` is a test-time interop oracle only, with no runtime dependency.

## Considered Options

- Full matrix (CAdES, PAdES, XAdES, ASiC) in 1.0: rejected as unrealistic for one maintainer.
- CAdES only: rejected. Signed PDFs are too large a share of Italian use.
